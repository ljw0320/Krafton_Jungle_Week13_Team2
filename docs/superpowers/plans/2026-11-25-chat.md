# 무작위 1:1 채팅 구현 계획

> **For agentic workers:** `AGENTS.md`를 따른다. Task마다 표시된 담당에게 맡긴다. `superpowers:subagent-driven-development`가 있으면 쓰되 프로젝트 규칙이 먼저다. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 브라우저가 8080의 내 서버를 거쳐 무작위 상대와 글과 이미지를 주고받는다. 5,000명이 동시에 써도 서버와 `chatd`가 죽지 않고 글이 사라지지 않으며, 실제 요청의 흐름을 화면으로 본다.

**Architecture:** 서버는 WebSocket 요청을 프록시로 `chatd`에 넘기고 `101`이 오면 `tunnel.c`가 두 소켓 사이의 바이트를 옮긴다. `chatd`는 자기 epoll 루프에서 핸드셰이크, 프레임, 매칭, backpressure를 맡는다. 프레임과 섞기는 소켓을 모르는 `ws.c`, `room.c`에 둔다.

**Tech Stack:** C (gnu11), gcc 13.3, POSIX 소켓, `epoll` LT, Make. 화면은 HTML/CSS/JS. 봇과 테스트는 Python 3.12 표준 라이브러리와 bash. WSL2 Ubuntu 24.04.

**Spec:** `docs/architecture-chat.md`. 상수, 상태 코드, 메시지 형식, JSON 키, 엣지 케이스 표는 설계를 따르고 여기서 다시 적지 않는다. 절 이름은 큰따옴표로 가리킨다.

## 실행 방법

- **공통 확인** (코드 Task의 끝, 셋 다 종료 코드 0)
  1. `make clean && make >/tmp/make.log 2>&1 && ! grep -q warning /tmp/make.log`
  2. `make clean && make test`
  3. `make clean && make test CFLAGS='-std=gnu11 -Wall -Wextra -g -fsanitize=address,undefined'` (끝나면 `make clean && make`)
- 포트: 서버 8080, `chatd` 9001, 터널 시험 백엔드 8004, 꺼진 백엔드 8009. 시험 전에 비어 있는지 본다. 포트를 쓰는 확인은 한 번에 하나만 돌린다.
- 시계: 서버 타이머는 `time()`이므로 테스트도 `time.time()`으로, `chatd` 타이머는 `CLOCK_MONOTONIC`이므로 `time.monotonic()`으로 잰다.
- 실험 파일은 레포 밖에 둔다.
