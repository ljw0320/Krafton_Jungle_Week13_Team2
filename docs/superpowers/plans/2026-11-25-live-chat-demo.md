# 공용 채팅방과 백엔드 비교 데모 구현 계획

> 구현은 `AGENTS.md`와 `superpowers:subagent-driven-development`에 따라 진행한다. 한 페이지에서 수동 채팅과 고정 봇 시험을 실행하는 범위를 승인받았다.

**목표** 한 공용방에서 실시간 텍스트를 주고받고, 봇 10명이 참여했을 때 백엔드 1개와 2개의 연결 배정 및 메시지 전달을 브라우저에서 비교한다.

## 제안 설계

- `/live.html`에서 `/ws/live`로 연결한다. 기존 `/ws/chat`은 1:1 채팅을 계속 처리한다. 공용방은 쓴 사람을 포함한 모든 접속자에게 글을 보낸다. 현재 접속 중인 사람에게만 전달하며, 텍스트 최대 크기는 기존 한도인 4,096바이트를 사용한다.
- 기존 리버스 프록시 라운드 로빈으로 새 WebSocket 연결을 배정한다. C로 작성한 루프백 중계 프로세스 `livehub`가 글의 순서를 정하고 각 `chatd`에 한 번씩 전달한다. 각 `chatd`는 자기 연결에 글을 전송한다. 두 구성에서 같은 중계 경로를 사용한다.
- 각 `chatd`의 기존 송신 큐를 쓴다. 큐가 가득 찬 연결만 닫는다. 시험 도중 중계 연결이 끊기거나 봇이 이탈하면 화면에 실행 실패를 표시한다.
- 로컬 실행 스크립트는 루프백에서만 페이지와 고정 시험 API를 제공한다. 페이지에서 시험 버튼을 누르면 API가 백엔드 1개와 2개를 차례로 실행한다. 수동 채팅은 별도의 상시 공용방 연결을 사용한다. 시험은 격리된 로컬 프록시와 백엔드에서 실행하므로 수동 메시지나 접속으로 봇 수치가 바뀌지 않는다.
- 시험 API와 WebSocket은 같은 브라우저 출처에서만 사용한다. 실행 중인 시험이 있으면 새 시험을 거절한다. 데모는 자신이 시작한 프로세스만 정리한다.

## 동일한 시험 조건

| 항목 | 백엔드 1개 | 백엔드 2개 |
|---|---|---|
| 새 WebSocket 연결 | `A`에 10명 | `A`와 `B`에 각각 5명 |
| 발신 | 연결 확인 후 방 전체 초당 2건, 15초간 30건 | 동일 |
| 기대 수신 | 각 봇 30건, 합계 300건 | 동일 |
| 비교 지표 | 백엔드별 연결 수, 실제 수신 수, 누락·중복, 전달 지연 p50·p95 | 동일 |

각 봇에 발신 순서를 배정하고 두 회차에 동일한 텍스트와 간격을 사용한다. 두 회차는 동시에 돌리지 않는다. 지연은 같은 WSL 호스트의 단조 시계 기준 발신부터 수신까지 잰다. 봇 10명은 분산과 전달을 설명하기 위한 규모이고, 지연은 해당 실행의 관측값으로 표시한다.

## 브라우저 화면

- `/live.html`에는 공용 채팅 목록과 입력창을 둔다. 텍스트는 `textContent`로 표시한다.
- 같은 페이지에서 **봇 10명 시험**을 시작한다. **백엔드 1개**와 **백엔드 2개** 비교 카드에 실제 연결된 봇을 백엔드별로 표시하고, 최근 글과 실제 전달 수, 누락·중복, p50·p95를 보여 준다. 두 백엔드 구성에서는 A와 B 사이에서 실제로 받은 글의 수신 결과가 카드에 드러나야 한다.
- 실행 상태는 대기, 실행 중, 완료, 실패로 표시한다. 실행 전에는 측정 지표를 비워 두고, 두 번째 회차가 진행될 때 첫 회차 결과를 유지한다.

## 구현 단위

1. **공용방과 중계** · `builder_high` / `verifier_high`. `chat/chatd.c`, 새 `livehub` 소스와 `Makefile`을 담당한다. `/ws/live` 연결을 추가하고, 한 백엔드에서 글 1건이 세 탭에 전달되는지 확인한다. 두 백엔드에서도 양쪽 사용자가 동일한 순서로 수신하는지, 큐가 가득 찬 연결을 닫아도 다른 사용자가 계속 받는지 검증한다.
2. **로컬 실행과 봇 측정** · `builder` / `verifier`. 기존 `tests/chat_bot.py`의 WebSocket 클라이언트를 재사용하고, 새 실행 스크립트가 두 구성을 순차 실행한다. 봇은 자기 백엔드 ID와 수신한 메시지 번호를 기록한다. 중복·누락·순서 불일치·중계 장애가 발생하면 실패로 기록한다. 기본 실행에서 `10 대 0`, `5 대 5`, 양쪽 `300건 수신`을 확인한다.
3. **공용방과 비교 화면** · `builder` / `verifier`. `www/live.html`과 `www/live.js`에 공용방, 시험 시작 버튼, 진행 상태와 비교 결과를 구현한다. 두 백엔드에서 연결 수가 바뀌어도 페이지가 실제 값을 그대로 보여 주고, 실패한 회차가 성공처럼 표시되지 않는지 확인한다.
4. **통합 시연** · `final_reviewer`. WSL에서 로컬 실행 스크립트로 두 회차를 재현한다. 마지막으로 기존 1:1 채팅이 정상이고 실행 종료 후 사용한 포트가 비었는지 확인한다.
