# 자원 부족 시 서버 생존

사용자가 요청한 재평가 1번만 수정한다. 로그 역압·응답 지연·헤더 처리 비용,
CGI 종료 대기·파일 전송 방식·빌드 분리는 이번 범위에서 변경하지 않는다.

## 구현

1. FD 한도 32, 전체 자식 상한 64의 실제 TCP 테스트에서 기존 부모 종료를 확인한다.
2. accept·socketpair·fork 자원 오류를 단위 테스트로 주입한다.
3. 자원 부족이면 새 연결과 준비된 채널을 닫고 부모는 생존한다.
4. 단조 시계의 고정 100ms 기한 동안 리스너만 제외하고 ppoll로 IPC·시그널을 처리한다.
5. 자식을 계속 회수하고 자원이 풀리면 수락을 재개한다. 연속 오류 진단은 억제한다.
6. 예상하지 못한 오류의 실패 정책을 보존하고 전체 테스트·sanitizer·코드 리뷰를 수행한다.

## 검증할 경계

- EMFILE·ENFILE·ENOMEM·ENOBUFS·fork EAGAIN에서 부모가 종료되지 않는다.
- 실패한 수락·채널 생성·fork가 연결이나 fd를 남기지 않는다.
- ppoll이 EINTR로 깨어나도 100ms 기한과 리스너 제외를 유지한다.
- 포화 중에도 기존 연결의 백엔드 획득·반납 IPC가 동작한다.
- 두 번의 포화·해제 후 새 요청과 fd·슬롯 수가 정상 복구된다.
- EINVAL 같은 예상하지 못한 오류는 계속 실패로 보고한다.

## 현재 결과

기존 구현에서 FD 부족 후 연결 거절·부모 종료를 재현했다.
수정 후 실제 FD 포화 복구와 자원 오류 주입 테스트를 통과했다.
일반 빌드의 전체 make test 및 ASan·UBSan make sanitize 통과(프록시 35개).
읽기 전용 별도 코드 리뷰에서 수정이 필요한 문제는 발견되지 않았다.
