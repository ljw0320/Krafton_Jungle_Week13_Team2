# 프록시 버퍼 2초 대기 비교 시험 — 2026-11-25

이전 코드 `9b98489`와 대기 정책 적용 코드 `8edda04`를 WSL에서 비교했다.
프록시 버퍼는 8개, 연결 슬롯은 64개로 설정했다. 동시 요청 16·32개가
연결 슬롯 제한에 걸리지 않고 버퍼 상한을 넘도록 하기 위한 설정이다.
빈 POST /echo를 요청별 새 연결로 보내고 Connection: close를 사용했다.
스레드 장벽으로 요청 시작을 맞췄지만 소켓·서버에 도착하는 시각까지 같지는 않다.
각 조건은 변경 전후를 번갈아 3회 실행했다. 장시간 처리량 시험은 아니다.

실제 서버는 현재 설정을 유지했다. 추가로 모의 백엔드가 요청당 100ms 또는
800ms 기다린 후 200·Content-Length: 0을 보내도록 하여 포화를 재현했다.
최종 모의 백엔드의 listen 대기열은 128이다. 기본 대기열로 실행한 예비 결과는
접속 지연이 섞여 최종 비교에서 제외했다. 지연에는 연결 수립부터 응답 본문
완료까지가 포함된다. p95는 성공·503을 포함한 전체 요청의 최근접 순위 값이다.

| 백엔드 | 동시 요청 | 변경 전 성공/503 (매 회) | 변경 후 성공/503 (매 회) | 변경 전 p95 범위 | 변경 후 p95 범위 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 실제 서버 | 16 | 16/0 | 16/0 | 10.70–12.26ms | 10.42–11.08ms |
| 실제 서버 | 32 | 32/0 | 32/0 | 19.53–21.30ms | 19.96–21.47ms |
| 고정 100ms | 16 | 8/8 | 16/0 | 113.14–119.13ms | 219.88–224.42ms |
| 고정 100ms | 32 | 8/24 | 32/0 | 121.08–126.05ms | 427.91–432.07ms |
| 고정 800ms | 16 | 8/8 | 16/0 | 814.84–817.47ms | 1619.56–1622.00ms |
| 고정 800ms | 32 | 8/24 | 24/8 | 823.89–827.14ms | 2430.14–2437.65ms |

변경 후 최대 지연은 실제 서버 16개 11.08ms·32개 21.62ms,
100ms 백엔드 16개 224.42ms·32개 432.72ms,
800ms 백엔드 16개 1622.00ms·32개 2438.25ms였다.

버퍼 대기는 포화 시 거절할 요청 일부를 정상 완료시키는 효과가 있었다.
처리량 자체를 높인다는 증거는 아니며, 성공 증가와 함께 완료 지연도 늘어난다.
800ms·32개에서는 8개씩 약 0초·0.8초·1.6초에 버퍼를 받고, 마지막 8개는
2초 안에 받지 못해 503이 된다. 세 번째 묶음은 기한 안에 버퍼를 받았으므로
응답 완료가 약 2.4초여도 정상이다. 2초는 대기 제한이며 전체 응답 제한은 10초다.
실제 빈 POST는 빨리 끝나 이번 규모에서는 기존 정책도 포화 거절을 재현하지 못했다.

36개 조건 실행 모두에서 추가 동시 요청 8개가 전부 정상 완료됐다.
각 실행 후 프록시 앞단과 백엔드 리스너의 ESTABLISHED 연결은 모두 0개였다.
이는 버퍼 재사용과 연결 회복 확인이며 모든 내부 버퍼의 직접 계수는 아니다.
내부 버퍼 반환·대기열 제거는 별도 C 단위 검사에서 확인했다.
make test_proxy도 통과했다: C 검사 4종, 기존 TCP 11개, 새 TCP 3개.
C10K와 지속 부하에서의 지연·공정성은 이 시험으로 검증하지 않았다.

재현 스크립트: tests/measure_proxy_buffer_wait.py.
먼저 artifacts/proxy_wait_before에 이전 실행 파일을 빌드해야 한다.

```sh
mkdir -p artifacts
git show 9b98489:proxy/main.c > artifacts/proxy_wait_before.c
cc -D_GNU_SOURCE -D_POSIX_C_SOURCE=200809L -D_FILE_OFFSET_BITS=64 -std=c11 -Wall -Wextra -Wpedantic -Werror -g -Isrc -Iproxy artifacts/proxy_wait_before.c proxy/headers.c src/http.c -o artifacts/proxy_wait_before
make all reverse_proxy
python3 tests/measure_proxy_buffer_wait.py
```

원시 결과는 artifacts/proxy_buffer_wait_results.json에 저장된다.
