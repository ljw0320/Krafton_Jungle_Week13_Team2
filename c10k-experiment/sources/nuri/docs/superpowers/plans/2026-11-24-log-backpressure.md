# 로그 역압으로 인한 요청 정지 방지

요청 범위: 웹서버 재평가 2번. 실행 중 stderr 파이프가 차더라도
부모와 연결 자식이 계속 처리하도록 한다. 응답 지연·헤더 비용·CGI·파일 전송은 제외한다.

## 구현

1. 가득 찬 파이프로 오류 응답이 정지하는 선행 TCP 회귀 테스트를 확인한다.
2. log/diagnostics.c에 상태 없는 best-effort 출력 함수와 errno 진단 함수를 둔다.
3. 파이프·터미널은 /proc/self/fd/2를 독립 O_NONBLOCK fd로 잠시 연다.
   소켓은 호출별 MSG_DONTWAIT를 사용한다. 파일은 원래 fd를 사용한다.
4. 부모의 perror/진단과 프록시 로그를 공통 함수로 연결한다.
5. 테스트·README·빌드 의존성을 갱신하고 전체 테스트·sanitizer·코드 리뷰를 수행한다.

## 보존할 계약

- 실행 프로그램과 다른 프로세스가 공유하는 stderr OFD 플래그를 변경하지 않는다.
- 원래 errno, 파일 위치, 로그 한 줄 형식, 부모의 진단 억제 정책을 보존한다.
- 로그를 큐에 쌓거나 별도 프로세스·상시 fd를 추가하지 않는다.
- EAGAIN·소비자 종료·임시 fd 생성 실패 시 유실을 허용한다.
- 일반 파일 디스크 지연과 시작 전 CLI/설정 stdio 진단은 범위 밖이다.

## 검증

선행 테스트에서 가득 찬 로그 파이프가 오류 응답을 막는 것을 재현했다.
포화 파이프·소켓·가상 터미널에서 오류 응답, 부모의 FD 부족 처리,
로그 출력 복구, 원래 fd 플래그와 fd 수 유지를 검증한다.
닫힌 소비자, 일반 파일의 기존 내용도 검증한다.
일반 빌드 전체 make test와 ASan·UBSan 전체 테스트를 통과했다(프록시 40개).
최초 sanitizer 실행에서 기존 FD 검사 타이밍의 경쟁 조건을 발견했다.
동시 수락 중 자식 목록 조회 뒤 fd가 6→9로 일시 증가하고 정리 후 6으로
복원됨을 재현했다. backlog 뒤의 요청을 처리한 후 자식·fd 수를 함께
확인하도록 테스트를 동기화하고 전체 sanitizer 테스트를 다시 통과했다.
읽기 전용 별도 코드 리뷰에서 수정할 문제는 발견되지 않았다.
