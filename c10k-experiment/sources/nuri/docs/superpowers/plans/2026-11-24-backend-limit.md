# 백엔드별 동시 처리 제한

사용자가 승인한 범위: IPv4·포트별 공유 상한, 요청별 획득·반납,
CLI `--backend-limit N`, 기존 전체 자식 상한 유지, 포화 시 즉시 503.
서버 공통 연결 수명·응답 전체 기한·HTTP 호환성 확장은 제외한다.

## 설계

부모가 자식별 제어 채널과 현재 점유 백엔드를 보관한다.
자식은 SOCK_SEQPACKET 채널로 획득·반납을 요청하고 결과를 확인한다.
부모만 점유 상태를 변경하므로 공유 메모리 잠금이나 분산 카운터는 없다.
자식 회수·채널 종료 시 점유 상태를 지운다. 종료 유예에도 요청을 처리한다.
부모는 ppoll로 리스너와 채널을 함께 감시하고 시그널 대기를 원자적으로 전환한다.

기본 상한 16, 허용 범위 1~4096은 이번 구현의 기본 정책이다.
본문 수신 후 백엔드 접속 직전부터 소켓 종료·중계 완료까지 슬롯을 점유한다.

## 실행 순서

1. tests/test_proxy.py에 한도·서비스 격리·회수 회귀 테스트를 추가하고 미구현 실패 확인.
2. main.c에서 위치 인자 뒤 두 옵션을 파싱·검증하고 server_run에 상한 전달.
3. proxy/routes.c에서 같은 주소·포트에 동일 backend_id 부여.
4. server/server.c에서 자식별 채널·슬롯·ppoll·종료 유예·비정상 회수 처리.
5. proxy/proxy.c에서 접속 전 획득, 모든 완료 경로 반납, 포화 시 503·close 처리.
6. README 갱신, 전체 make test와 sanitizer 검증, 읽기 전용 코드 리뷰.

## 검토할 경계

- 경로가 달라도 주소·포트가 같으면 공유하되 다른 포트는 독립적이다.
- keep-alive 대기에는 미점유하며 요청별 다른 백엔드 선택이 가능하다.
- 실패·클라이언트 취소·SIGKILL에서 슬롯을 잃지 않는다.
- 종료 유예 중 슬롯 반납 ACK를 기다리며 교착하지 않는다.
- 제어 채널은 exec 시 닫고, 새 자식에 다른 자식의 채널을 남기지 않는다.

## 검증

선행 테스트에서 CLI 옵션 미지원으로 실패하는 것을 확인했다.
한도·격리·keep-alive·강제 종료·취소·종료 유예·옵션 순서 7개 통합 테스트 추가.
일반 빌드의 전체 make test 통과(프록시 31개).
ASan·UBSan 전체 테스트 통과(프록시 31개).
최초 sanitizer 실행에서 기존 취소 테스트의 단계 동기화 부족을 발견했다.
클라이언트가 응답 헤더를 수신한 뒤 취소하도록 보강하고 전체 검증을 다시 통과했다.
읽기 전용 별도 코드 리뷰에서 수정이 필요한 문제는 발견되지 않았다.
