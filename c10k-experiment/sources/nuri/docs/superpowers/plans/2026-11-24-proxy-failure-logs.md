# 프록시 실패 로그 개선

사용자가 승인한 범위: stderr 한 줄 로그에 백엔드 IPv4·포트, 매칭된 설정 경로,
슬롯 획득 요청 시작부터 실패까지의 경과 시간, 명시적인 실패 이유를 추가한다.
기존 단계·상태·본문 바이트 수는 유지한다. 원래 URL·쿼리·헤더·본문은 제외한다.
정상 접근 로그·별도 로그 시스템·HTTP 호환성 확장은 추가하지 않는다.

## 실행 순서

1. 실제 TCP 검증 오류·동시 실패·슬롯 포화 테스트를 추가하고 기존 구현의 실패 확인.
2. proxy/headers.c의 응답 검증 결과에 고정 실패 이유 문자열을 추가한다.
3. proxy/proxy.c의 입출력 실패에 이유와 실제 시스템 오류를 즉시 보관한다.
4. 슬롯 거부·반납 실패도 공통 실패 정리와 단일 로그 경로로 연결한다.
5. 테스트·README를 갱신하고 전체 테스트, sanitizer, 읽기 전용 코드 리뷰를 수행한다.

## 경계

- 시스템 오류와 HTTP 검증 오류·타이머·EOF·연결 취소를 구분한다.
- 정리 중 슬롯 반납 오류가 원래 실패를 덮어쓰지 않는다.
- 응답 시작 후 새 오류 응답을 덧붙이지 않는다.
- 동시 요청 로그를 짧은 단일 write로 기록한다. 긴 설정 경로는 256바이트로
  제한하고 route_truncated 필드로 표시한다.
- 경과 시간은 CLOCK_MONOTONIC 기반이며 조회 불가 시 -1이다.

## 검증

선행 TCP 테스트에서 필드 누락과 슬롯 포화 무로그를 확인했다.
새 로그 TCP 테스트 3개 및 연결 거절·EOF·타임아웃·취소·포화 검증 통과.
일반 빌드 전체 make test 통과(프록시 34개).
ASan·UBSan 전체 make sanitize 통과(프록시 34개).
읽기 전용 별도 코드 리뷰에서 수정이 필요한 문제는 발견되지 않았다.
