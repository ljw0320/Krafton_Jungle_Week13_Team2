# 구현 결정 요약

- 대상: macOS / WSL / Linux, C17, Makefile, 표준 C·POSIX API만 사용.
- 구성: `main` / `server` / `thread_pool`의 3개 C 모듈.
- 기능: 정확한 `GET /`에 고정 HTML(`Web Server`, `Hello, World!`). POST·정적 파일·프록시 제외.
- HTTP/1.1 keep-alive, HTTP/1.0은 응답 후 종료. pipelining 제외: 수신한 다음 요청 데이터가 있으면 첫 응답 후 종료.
- GET 본문은 길이 0만 허용. chunked 미지원. 404·405 외 HTTP 오류는 400, 텍스트 설명 후 종료.
- 메인 accept + 고정 워커 4개. 워커는 연결 하나를 종료까지 담당. 모든 소켓 non-blocking, 대기는 poll(). 다중 연결 이벤트 루프 제외.
- 기본값: `127.0.0.1:8000`, 연결 큐 64, backlog 64. 큐 포화 시 accept 중단, 큐 체류 제한 없음.
- 워커별 고정 헤더 버퍼 재사용. 요청 줄·헤더 전체 한도 16KiB, 연결당 최대 100요청.
- keep-alive 유휴·헤더 수신·전송 타임아웃 각각 5초. 수신·전송은 무진행 시간 기준.
- 주소·포트·워커·큐·backlog·SO_REUSEADDR·세 타임아웃은 CLI로 변경. 기본값은 코드에서도 수정 가능.
- SO_REUSEADDR 기본 활성화. bind 실패는 원인 출력 후 실패 종료. accept 자원 부족도 종료 절차 시작.
- 로그: 시작·종료·오류·연결 수락·연결 종료.
- SIGPIPE 전체 무시. SIGINT·SIGTERM은 sigaction + self-pipe로 전달.
- 종료: accept 중단, 큐·유휴 연결 정리, 현재 요청 하나만 최대 5초 기다림. 추가 신호 무시.
- 테스트: Python 3 표준 라이브러리. 기능 테스트와 TCP 유지·반복 GET 부하 테스트.
- 부하: 기본 설정으로 동시접속 1/4/16/64/128/1000, 최초 연결 시도 후 단계별 10초. 클라이언트 접속·GET 제한 각각 5초. **추가 사용자 요청으로 10,000 접속 단계는 생략한다.**
- TCP 유지 실험은 재접속 없음. 연결 성공·실패·종료·잔존 수, GET 성공·실패·RPS·p50/p95/p99 보고.
- 결과물: 빌드·실행 안내, 설계·동시성 모델 비교, 학습용 주석, 테스트 도구, 시연 절차, 실제 부하 결과.

사용자가 위 결정을 승인하고 이 요약 저장 및 구현 시작을 허락함. 완전한 HTTP/1.1 구현이 아닌 학습용 제한을 명시한다.
